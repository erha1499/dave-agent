# 知识与检索基线

2026-10-04 完成 P0：固定参考语料导入、标签校验、与业务端共享的关键词排序，以及可复现的逐题检索报告。当前不改写知识、不新增检索算法；先记录原始表现，再按相同题集比较后续改动。

## 运行

```sh
node scripts/retrieval-check.ts
node scripts/retrieval-baseline.ts
```

无需数据库、模型凭据或网络。数据与口径检查已纳入 `npm run check` / `npm run validate`；基线命令输出 `.runtime/retrieval-baseline.json` 和 `.runtime/retrieval-baseline.md`。JSON 包含每题输入、相关标签、完整排名、前五条、失败原因、hard 类型分组、数据/代码 SHA256、Git 状态和 Node/ICU/locale。重复运行会覆盖这两个本地报告，比较版本前应另存旧报告。

参考数据来自固定 [kefu-harness commit](https://github.com/wanglongze123/kefu-harness/tree/305590129ea020a5a362e07b294fd1587b8f53fd)。原始 35 篇文档、136 道常规题、76 道难题与 MIT 许可、原作者说明按原字节保存；[来源清单](../data/reference/kefu-harness/source.json) 记录哈希、字节数和筛选规则。[数据说明](../data/reference/kefu-harness/README.md) 记录字段、选择理由及政策差异。加载时检查 SHA256、schema、重复输入、相关文档缺失、范围与 ctx 类型；异常直接失败，不跳题或悄悄修标签。

## 语料与业务边界

| 评测范围 | 文档 | 常规题 | 难题 |
| --- | ---: | ---: | ---: |
| 餐饮退款/核销选集 | 11 | 44 | 26 |
| 完整参考集 | 35 | 136 | 76 |

选集预先固定为 CY001–CY003、RF001–RF005、VF001–VF002、MC002；只保留相关标签全部在选集内的问题。它是完整集的子集，两组成绩不合并，也不能把选集分数当成完整集分数。原行号作为稳定题目 ID，标签从不参与查询改写、候选排序或逐题选择文档。

这些构造规则只作为独立离线语料，不写入 `knowledge_documents`，不自动映射到演示门店。RF001 的免商家同意、过期退款和 RF005 的真实到账、平台页面描述与当前模拟业务不同；店铺活动还可能已过期。客服继续使用原有 8 篇规则及宿主授权边界。若以后接入业务端，需另建经适配的规则版本及对应标注。

生产 `search_faq` 和本报告共用 `src/knowledge-retrieval.ts`：按 query 包含 tags 的数量计分，零分排除，按分数降序、文档 ID 排同分。业务端保留原数据库范围校验、最多 200 个候选和前 5 条输出。离线参考集按显式 `shopId` 过滤店铺文档；行业及 hard 的 `ctx` 原样保留但不用于改写。`ctx.verified` 是核销状态，不是身份认证。未知店铺在线会被数据库入口拒绝，离线过滤仅保证不返回别店文档，不能替代真实权限检查。

## 第一版结果

以下是本项目排序逻辑在原始参考标签上的基线，未调用上游检索器、Pi/模型或 QQ。真实客服还会通过模型生成 `search_faq` 参数，因此这些数值不是端到端客服通过率，也不是历史模型套件分数。

| 语料 | 题集 | 题数 | Recall@1 | Recall@5 | MRR | MRR@5 | 空召回 |
| --- | --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 11 篇选集 | 常规 | 44 | 47.73% | 59.09% | 0.5311 | 0.5197 | 13 |
| 11 篇选集 | 难题 | 26 | 3.85% | 3.85% | 0.0385 | 0.0385 | 25 |
| 35 篇完整集 | 常规 | 136 | 45.59% | 55.88% | 0.5011 | 0.4962 | 39 |
| 35 篇完整集 | 难题 | 76 | 11.84% | 11.84% | 0.1184 | 0.1184 | 64 |

Recall@k 先算每题相关文档在前 k 条中的比例，再宏平均；MRR 使用完整正分排名中第一个相关文档的倒数排名，MRR@5 限制在前五条。零命中记零；空分组显示未知。原题集每题只有一个标签，不能衡量多证据答案。检查脚本另用多标签、排名第六、空排名样例验证分母与截断，避免把命中率误写为一般 Recall。

额外 8 个原创样例单独报告：4 个店铺范围检查全部通过；4 个无答案问题有 2 个空返回，2 个仍返回泛化知识。后者说明“命中退款/停车标签”不能证明语料能回答退款利率或充电桩数量；这是召回诊断，不是模型幻觉率。无答案样例没有相关标签，不混入上述 Recall/MRR 分母。

## 失败与下一步

- 口语漏召回：选集 26 道难题中 25 道没有任何标签命中。优先检查同义表达和省略信息，而不是先更换 Harness。
- 同分挤出：例如 `standard-0019`“怎么查退款进度”，RF005 排在第六；只有“退款”标签命中，ID 同分排序让其他规则占据前五。
- 相关不等于可回答：未知细节可能召回泛化文档；需要在后续回答评测中验证 Agent 明确未知，不能只看召回非空。

P1 用这份固定基线对照检索与上下文处理方案，分别记录 query-only 和使用 ctx 的实验；选集与完整集、常规与难题继续分开。调整后还需回归真实 MySQL / Pi 工具链的门店、套餐、归属和未知政策边界。当前数据未划分独立调优/留出集；直接针对固定题集改进只能说明这份基准上的变化，不能宣称对未见问法的泛化提升。

本轮类型检查、数据/指标检查、完整 `validate` 和 `check:business` 通过；排序抽取保持原算法，未重跑真实模型。报告为独立检索产物，尚未接入评测工作台的 Recall/MRR 展示；既有工作台的模型、工具和 usage 口径保持原样。
