## 本地预算的名称与计算

策略名称固定为 `utf8-byte-plus-output-v1`，单位称为“**本地预算单位**”。一字节 UTF-8 serialized payload 按一个输入预算单位计算，再加上请求声明的输出 Token 预留和固定余量：

```text
payloadUnits = UTF8ByteLength(finalSerializedBody)
requiredUnits = payloadUnits + requestedOutputTokens + safetyUnits
effectiveLimit = min(applicationLimit, catalogContextWindow)
允许发送条件：requiredUnits <= effectiveLimit
```

离线校准后，正式默认 `applicationLimit=65536`、`safetyUnits=1024`；本批 CXT 验收单独固定 `applicationLimit=30000`。原拟定 32768 会截住常规退款多轮的部分请求，却不能在 CXT-02 第一跳拒发，不能沿用。正式配置 `MODEL_CONTEXT_BUDGET_UNITS` 接受 4096..262144 的严格十进制整数，省略取 65536；空值、空白、前导零、小数和越界均拒绝。配置、实际生效值和策略版本进入快照，不提供跳过预算的开关。验收用 30000 的结果不能推广为默认 65536 下这条 4844 字输入一定拒发；两者必须分别报告。不能看过本批真实回答后调整阈值或输入。

这是一种刻意保守、可复现的工程预算：**它不是精确 tokenizer 的 Token 数，也不是供应商保证的上下文容量。** payload 中 JSON 结构、系统消息、工具定义也计入；目录 `contextWindow` 是本地模型元数据，不证明远端服务当天实际提供相同窗口。输出 Token 与输入字节在这个策略中按声明的权重组成预算单位，不能对外称为实际消耗 Token 总数。

输出预留取最终 body 中实际发送的 `max_tokens` 或 `max_completion_tokens`。必须是唯一明确、合法的正整数，并不超过当前会话已批准的输出上限：主 Agent/support 当前为最多 2048，question 为最多 1024；网页选择 512/1024 时取该会话更小的实际上限。缺失、冲突、非法值或无法识别的格式不能默默使用估计默认值继续发送。合法短请求仍沿用现有模型参数，不因本合同放大输出限额。

`requiredUnits` 恰好等于上限可以发送，超过一个单位即拒绝。整数范围、溢出和非法目录元数据均用纯检查验证。当前 M4 的完整上下文规则面向生成模型的 HTTP SSE；rerank/embedding 不套用生成模型输出预留含义，仍受 M2 实际 HTTP 上限约束。

## 拦截位置与测量口径

检查放在 [model-request-budget.ts](../src/model-request-budget.ts) 的实际 transport 之前，以 Pi 和项目 hook 最终生成的完整 JSON body 为依据。不能只统计用户输入，不能只累计历史消息，也不能只在 `before_provider_request` 扩展中抛错：当前 Pi 会捕获该扩展异常。

完整检查包含系统 Prompt/Skill、历史消息、工具 schema、本轮用户输入、已经回填的工具结果以及输出参数。工具结果增长后，下一次模型调用再次检查。拒发时实际 HTTP 增量为 0，`blockedRequests` 和固定原因保留；M2 的 12 次 HTTP 预算不重置。

不得删除旧消息、截断工具结果、去掉来源或确认条件来自动挤入窗口。业务执行已经完成而最后一次解释被拒发时，继续使用原有受控回执或结果查询；不能为补一句解释再次准备方案或执行写入。

三类测量分开保存：

| 测量 | 能说明什么 | 不能说明什么 |
| --- | --- | --- |
| 最终 payload 字节、本地 requiredUnits、输出预留 | 本地策略为什么允许或拒绝这次发送 | 精确供应商 Token 用量 |
| Pi `getContextUsage()` 的 tokens/percent | SDK 对会话投影的上下文估计，可为 null | 下一次完整 body 一定装得下，或系统/工具均已算入 |
| M2 实际 wire usage | 已发送请求返回的 prompt/completion/cache 用量 | 未返回用量的费用为零，或远端收到取消就立即停止计费 |

日志只记录数值、策略/模型元数据、固定失败原因和请求摘要；不保存完整 body、用户长原文、工具长结果或 header。拒发诊断不能伪造一条“已发送但用了 0 Token”的记录。

## 默认 atomic 的恢复合同

| 入口 | 超限后的动作 | 下一次正常使用条件 |
| --- | --- | --- |
| QQ | 取消并等待旧工作结清，沿用失败后的 Session 销毁/重建路径 | 用户重新写明订单和完整诉求；新 Session 不沿用旧会话焦点 |
| 网页 | 沿用失效与持久历史保留路径，给出明确的新建对话提示 | 新建对话后重述；重开原历史会重新注入同一内容，不能承诺仅重连就解决 |
| CLI | 将固定 Session 改为会话工厂管理；超限后等待 abort/旧工作结清、dispose，再创建新 Session | 清空原 Pi 消息和随 Session 绑定的 OrderDiscovery 状态，不自动重试原长请求；下一轮明确重述 |

提示文字应说明“本次上下文已超过当前处理范围，请新开对话并写明订单号及完整问题”。不能声称“我已压缩并保留所有重要信息”。网页必须明确区分查看旧记录与在新对话继续。

已保存的商家任务、退款操作、幂等记录和已成功业务结果保持可查询。上下文保护不负责删历史、撤销已完成业务或迁移确认；确认仍走原宿主入口和当前服务校验。

**Controller + 持久引用是独立边界。** 只清 Pi 消息或调用现有 `cancelSupportTurn`，不会证明内存订单焦点和 MySQL 引用已经安全清空。此批次不声称实现该候选的自动焦点清除或完整重建验收。如未来扩展到它，须等待旧引用写入结清、按 CAS 写入 `requiresRestatement` 状态，并验证重建后不会重新载入旧焦点；另行履行相应实库合同。不能在文档中把默认 atomic 的恢复通过推广到该候选。

## 付费前的离线校准与纯检查

先使用已安装 Pi 的真实请求构造与本机合成 HTTP，把下面四题的原文、固定工具结果、模型配置、完整 payload 字节与阈值冻结。只观察字节与调用合同，不运行远程模型。短题按预期工具链生成最末次请求，确认仍有余量；长输入和长工具结果必须确定性越界。

本次离线校准已采用正式默认 65536 / 验收 30000 的分离配置，理由和实测值见下表。验收独立阈值不修改正式入口默认值，不能把该批结果描述成默认阈值下的长原文拒发验收。

纯检查至少覆盖以下合同；付费批次不重复逐一跑这些边界：

1. 系统流程、工具 schema、当前用户输入和新工具结果分别单独使完整请求越界；底层 transport 均为 0 次。
2. 输出预留缺失/冲突/非法、预留加余量恰好达到上限、超过一单位、未知模型元数据和不支持格式。
3. hook 抛异常不能绕过最终 guard；HTTP/Pi 重试和被外部运行器替换的 transport 仍通过同一预算。
4. 工具已经执行后下一跳超限，工具执行次数不增加，已有业务回执仍可使用。
5. CLI 新 Session 不携带旧消息和选单焦点；模糊“那张”不能靠旧历史继续；网页原历史重开仍可能拒发，新建对话可从明确问题开始；QQ 使用已有重建边界。
6. usage 缺失、半流、取消和已知用量分别保留；请求被拒发不填入虚构的实际 Token 或费用。

若这些检查或完整 `npm run validate` 未通过，不进入付费阶段。任何涉及持久存储语义的额外修改先完成专用实库检查；不能用这批只读上下文题代替。

## 真实批次预算、冻结与收尾

- 计划分母固定为上述 4 场景/4 输入；总授权上限仍为 6 场景/12 输入，剩余额度不是增题许可。
- 实际 HTTP 总计最多 40 次，包含失败与各层重试；单轮保持 M2 的 12 次上限，以先到者为准。候选 question/support/rerank 本批不启用。
- 15 分钟从开始受理本批第一条固定输入计时；达到期限停止新增请求、取消共享信号，随后安全结清旧工作并记录实际收尾耗时，不再启动下一题。
- 冻结源码与依赖版本、Prompt/Skill/hash、架构/模型、实际预算配置、题目与夹具/hash、运行 ID 和计划分母。必须在首次远程请求前完成。
- 一次执行完预定四题即收尾。达到任一预算、出现不能安全继续的授权/写入问题、实际网络无法受控计数或配置漂移时提前停止，保留未执行分母和原因。
- 保存各题放行/拒发、最后成功 HTTP 与下一跳拒发关系、工具次数、实际回复判定、恢复前后 Session 区别、已知/未知 Token 与分币种费用。结果不得把未知补零。
- 失败不改题追分。若确有新根因，先归档这一批，再按 P0 重新判断是否值得开下一份合同；本授权不自动续跑。

验收通过最多支持“默认 atomic 的完整请求受本地保守预算约束，超限可停止并在新会话重述”。它不能支持自动语义压缩质量、超大上下文生产容量、Controller 持久引用恢复、跨进程全局费用硬限额或真实商业运行的结论。
