# Dave-Agent 简历项目描述与职责模板

## 项目背景

**Dave-Agent｜本地生活智能客服 Agent｜Agent / 后端开发｜个人项目**

面向团购券咨询与售后，基于 Pi SDK、TypeScript 和 MySQL 构建客服 Agent，覆盖订单查询、规则解答、商家协商及退款确认。重点解决口语化诉求理解、跨轮订单切换和异步处理中的执行可靠性，负责 Harness 编排、检索优化、上下文治理与评测基建。

**技术栈：** TypeScript、Node.js、Pi SDK、MySQL、SQLite、QQ Bot SDK、SSE。

## 主要职责｜推荐简历版

- **Harness 建设：** 基于 Pi SDK 统一 CLI、QQ、Web 的会话装配、工具注册与生命周期管理；通过严格 Schema、可信身份注入和执行时授权，防止模型越权调用业务工具。
- **编排重构：** 将固定的数据查询、状态检查与结果通知下沉至 Controller，模型请求减少 **40%**、Token 消耗减少 **46.5%**；通过工具前置依赖与状态复核，防止跳步执行和历史授权复用。
- **检索优化：** 引入领域同义归一、中文分词与多字段加权，常规问题 Recall@5 由 **55.88% 提升至 80.15%**，困难问题由 **11.84% 提升至 44.74%**；通过门店与套餐范围过滤，防止规则串用。
- **证据接收优化：** 增加事实支持判别，无答案证据误接收率由 **22.22% 降至 0%**，接收后证据 Recall@5 保持 **96.67%**；通过候选绑定、原文引文校验与来源复检，拒收无依据或失效证据。
- **调用预算治理：** 利用 AsyncLocalStorage 统一主模型与检索组件的请求计数，将单条消息的 HTTP 请求限制为最多 **12 次**；将重试计入预算，发送前拦截超限及迟到调用，防止异常循环持续消耗额度。
- **事务与故障恢复：** 通过 MySQL 行锁、唯一约束与结果回读实现退款幂等；引入提交前后进程故障注入，保障未提交事务回滚、已提交结果可查，防止重复确认或结果回复丢失导致二次执行。
- **异步通知治理：** 拆分业务完成与消息投递状态，通过数据库条件更新和唯一领取，将每条通知限制为最多 **1 次**主动发送尝试；发送前重新授权，结果不明时保留查询恢复，避免盲目重发。
- **评测基建：** 建设场景、轮次、判据三级评测，关联模型调用、工具轨迹与持久状态；通过配置快照、固定回归和答复质量独立评分，定位版本退化，防止工具执行成功掩盖回答错误。

## 可替换职责｜按岗位选择

- **RAG 选型：** 统一词项、向量、融合与重排的比较链路，困难问题 Recall@5 由 **44.74% 提升至 97.37%**；通过范围过滤与证据支持校验约束结果，防止高相关资料被直接当作可用答案。
- **工具依赖治理：** 将订单、规则及商家状态固化为工具前置依赖，通过当轮范围与版本检查阻断跳步调用；退款准备重新读取批准状态，防止历史结果或用户转述绕过业务约束。
- **流式链路重构：** 统一业务卡片与 SSE 的回答依据检查，依据当轮工具结果生成回复并控制文本放行；缺证据或调用失败时自动降级，订单刷新时清理旧证据，防止过期卡片复用。
- **身份失效保护：** 在消息出队和回复发送前复核身份绑定，变化时重建 Session，读取失败时拒发并清理；结合工具执行时重新授权，防止旧会话历史与迟到回复跨身份复用。
- **取消与队列治理：** 重构超时、取消、会话销毁与队列释放顺序，等待模型循环及 Harness 后续异步处理结束后再处理下一轮；结合串行队列与迟到拒发，防止旧任务污染后续会话。
- **上下文持久化：** 将订单焦点、规则话题和任务引用从模型历史中分离，使用 MySQL、CAS 修订号与 TTL 保存业务引用；恢复时重新授权并查询当前事实，拒绝过期或冲突引用，防止上下文串单。
- **上下文预算：** 在请求发送前统一核算系统指令、工具定义、历史及工具结果，预留输出空间与安全余量；超限时停止模型调用并保留业务结果，避免补充答复触发重复执行。
- **Web 请求恢复：** 基于请求 UUID、owner CAS 与 SQLite 事务关联消息和请求结果记录，支持请求重放与已完成结果恢复；校验标签页会话版本，阻止旧请求和迟到响应覆盖新会话。
- **调用观测：** 按授权、模型、渲染、发送和展示登记拆分运行阶段，关联逻辑调用与实际 HTTP；通过脱敏账本记录耗时、重试及分币种费用，保留首次失败和缺失用量，避免成本漏计。
- **评测缓存治理：** 将缓存绑定请求、候选、模型配置及校验证明，通过哈希检查拒用不完整或失效结果；区分缓存回放与新增请求，避免旧结果污染版本比较或重复计入用量与费用。

## 短版项目背景

基于 Pi SDK、TypeScript 和 MySQL 构建本地生活客服 Agent，围绕团购券咨询与售后，负责 Harness 编排、检索优化、上下文治理、事务可靠性及评测基建。

## 选用建议

先按岗位挑 5–7 条，再留下自己能讲深的内容。Agent 应用岗可优先组合 Harness、编排、检索、证据接收、调用预算和评测；后端岗可优先组合事务、异步通知、身份失效、队列和请求恢复。面试时为每条准备一个具体例子，指标口径统一查下表。
