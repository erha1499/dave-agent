# 6.1 网页选的模型，真的用到这次请求了吗？

## 从一次“应用设置”开始

你把网页客服的输出上限改成 512，点击“应用并新建对话”，随后问“我有哪些订单”。页面给出订单列表，但这不意味着刚才选的模型已经工作了：查最近订单可以由 Harness 直接完成。理解网页配置，关键是区分**保存设置**和**执行模型请求**两个时点。

本课走通表单、后端校验、会话快照和 Pi 调用。Pi 提供模型与工具循环；项目的 Harness 将它接到网页业务上，负责确定提问者身份、工具范围以及传给模型的实际参数。

## 先认清四个对象

| 对象 | 保存什么 | 什么时候变化 |
| --- | --- | --- |
| 表单草稿 | 用户尚未应用的选择 | 点击下拉框就会变化 |
| 配置快照 | 服务端接受的模型、推理档、输出上限 | 应用设置并建立新对话时 |
| 模型运行时 | 模型目录、提供商连接和服务端凭据 | 服务启动后按选择复用 |
| Agent Session | 当前对话的模型历史和执行状态 | 首次需要模型时创建，随对话推进 |

快照就是把用户已经应用的设置固定下来。你可以继续改表单，正在接待的对话仍按原快照运行。同一个连接运行时可以复用，但每段聊天都有独立的 Session。

输出上限使用 token，表示模型处理文本的单位，不能直接当成汉字数；开启推理也不能保证答案更好。

## 第一关：服务端只接受允许的设置

网页提供有限模型目录、`off/high` 推理档，以及整数 `512/1024/2048` 三个输出上限。客户端不能上传任意模型地址、密钥、身份或系统提示词。即使有人绕过界面直接发 HTTP 请求，后端也必须执行同样的校验。

服务端先把表单当作不可信输入，检查字段和值：

```typescript
// 未提交设置时采用服务端默认值；显式提交则必须完整。
const explicit = value !== undefined,
  input = explicit ? value : catalog.defaults;
if (!input || typeof input !== "object" || Array.isArray(input)) {
  throw new Error("模型设置必须是完整对象。");
}
const settings = input as Record<string, unknown>;
if (
  // 只收三个字段，多一个身份、地址或提示词字段也不接受。
  Object.keys(settings).length !== 3
  || Object.keys(settings).some(key =>
    !["modelSelection", "thinkingLevel", "maxTokens"].includes(key))
  || typeof settings.modelSelection !== "string"
  || !modelSelections.includes(settings.modelSelection as ModelSelection)
  || typeof settings.thinkingLevel !== "string"
  || !["off", "high"].includes(settings.thinkingLevel)
  || ![512, 1024, 2048].includes(settings.maxTokens as number)
) {
  throw new Error("模型设置须包含允许的模型、推理模式及整数输出上限。");
}
```

因此，绕过界面提交字符串 `"512"` 也不会成功：白名单中是数字，后端不会替客户端悄悄转换。

接下来还会检查模型支持的输出上限、推理档和本机配置。配置能解析，并不说明云端凭据或额度一定可用；这些问题可能到实际调用时才暴露。

## 第二关：校验成功，再替换活动会话

页面用 `POST /api/chat/session` 提交客户、当前页面认为有效的 `sessionId`，以及可选的完整设置。新页面没有活动会话时声明 `null`。服务端先核对参数和当前会话，再判断是否忙碌，最后建立新对话。顺序的意义是：无效设置不应让用户丢失当前接待状态。

当前实现保存已受理对话的公开记录，新建对话会切换活动 Session；它不把旧模型上下文继续混入新配置。以后打开旧对话时，仍沿用该对话保存的设置。

例如，已应用“模型甲、高推理、512”，你把表单改为“模型乙、关闭推理、1024”却没有应用，那么普通的新建对话仍沿用已应用设置。只有明确应用，后端才接受新的组合。

## 第三关：真正需要模型时才创建 Session

并非所有消息都需要模型。最近订单查询、完整到账规则命令等可先由 Harness 处理；需要普通问答时，才进入会话工厂。这叫懒初始化：把有成本的创建推迟到确实需要的时候。

确实需要模型时，先取得可复用的运行时，再创建这段对话的 Session：

```typescript
// 同一模型复用运行时；每段对话仍创建独立 Session。
let runtime = runtimes.get(settings.modelSelection);
if (!runtime) {
  runtime = createConfiguredModelRuntime(
    configuredEnv, settings.modelSelection);
  runtimes.set(settings.modelSelection, runtime);
}
// 缓存的是初始化任务（Promise）；命中缓存也要等完成，再取配置。
const configured = await runtime;
const session = await createCouponSession(
  identity, store, configured.modelRuntime,
  // 复制后改上限，不改共享对象。
  { ...configured.model, maxTokens: settings.maxTokens },
);
session.setThinkingLevel(settings.thinkingLevel);

// 从实际 Session 读回参数；没有生效就释放并报错。
if (session.thinkingLevel !== settings.thinkingLevel
  || session.model?.maxTokens !== settings.maxTokens) {
  session.dispose();
  throw new Error("所选模型参数未实际生效。");
}
```

运行时缓存复用的是连接配置。每次创建 Session 都复制模型配置、写入本对话上限，再读回推理档和上限核对，避免界面显示“已应用”而实际参数没有生效。

Pi 负责会话中的模型循环、工具事件和历史。项目补上目录校验、配置快照、身份隔离和业务工具组合。

## 把一条问答完整走通

假设小林应用了默认模型、关闭推理、512 上限，然后问“这张券周末能用吗”：

1. 浏览器发送当前 `sessionId`、新的 `requestId` 和原文。
2. 服务端核对浏览器访问凭证与客户绑定，确认这仍是活动会话。
3. Harness 检查是否能直接处理；普通问答需要模型时，使用该对话快照创建 Session。
4. Pi 发起模型调用。模型需要订单和规则时，只能调用注册的只读工具。
5. Harness 将本轮结果整理为公开回复，保存后返回页面。

如果用户改问“我有哪些订单”，第 3 步可能就由 Harness 返回本人订单列表，不必创建模型会话。两条路径都合法；判断配置是否实际进入模型，应查看真正进入模型的路径。

创建 Agent 后，还要确认实际注册的工具只有三项：

```typescript
// 网页只允许查本人订单、列订单和查规则，配置变更不能加写入工具。
if (agent.getActiveToolNames().sort().join(",")
  !== "get_order,list_orders,search_faq") {
  throw new Error("网页工具必须只读");
}
```

因此，换一个更强模型仍只会获得查订单、列最近订单和查规则的能力。底层业务数据库使用只读账户，再加一层限制。

## 为什么选择新对话，而不是原地切模型

原地切模型可以保留全部上下文，但必须处理在途请求、旧配置生成的历史以及新旧参数混用。这里采用“应用设置并新建对话”，让一段对话对应一份配置，代价是当前上下文不直接延续；旧公开记录仍可回访。

运行时缓存省去重复初始化，但也意味着服务端环境变化后需要重启。初始化失败的 Promise 会留在缓存里，新建聊天不会自动清掉它；这是当前有限模型目录所接受的取舍。

## 练习：预测错误会在哪一步发生

- 把 `maxTokens` 改成字符串 `"512"`：字段校验拒绝，尚未替换活动会话。
- 当前消息处理中点击应用：忙碌检查拒绝，不能用新会话插队。
- 配置能解析但云端凭据失效：保存设置可能成功，实际模型调用失败。
- 只改表单不应用：当前会话仍使用原快照。

面试时可以这样讲：我把网页选择变成受校验的会话配置，在首次需要模型时创建独立 Pi Session；复用运行时，但不混用客户历史。参数接线与回答质量分别检查，换模型不会扩大业务权限。
