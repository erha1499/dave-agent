# A1 离线证据接收：实现与固定验证

日期：2026-10-05。**离线实现和对照实验已完成；分数策略尚未达到上线准入。** 本轮未接入在线知识服务，未切换 QQ 配置，未重跑真实 QQ 或 24 个业务验证对话。6 道上下文题仍待 C1，不能称完整 60 题全部通过。

## 实现

- `src/evidence-acceptance.ts` 在原始排名之后按 `off` 或 `score` 接收最多 5 条原文。范围和 active 检查始终生效，策略不读取 gold；缺失分数、越权、失效和 provider 失败受控拒收，diagnostic fallback 不作为已接收证据。
- `scripts/retrieval-v2.ts` 分别保存 raw 排名、接收证据/拒收原因、成功与计划分母的指标，以及失败、缺项和延期。权限违规和“可见但不足以回答”的错误接收分开统计。
- 实验 config version 2 支持固定数据集和接收参数；version 1 保持旧语义。CLI/API/工作台使用相同校验与执行器。前端仍由 Kimi K3 + Max 完成。
- 新增 48 道开发题、60 道固定验证题，以及 24 个业务对话/79 轮的数据与冻结合同。[数据说明](./acceptance-data.md)明确共享工作区、非盲测、原文/范围和未执行部分。

## 先校准，再验证

先调用 M4 获得 48 题 raw 结果。校准前语义审阅修正两处等价证据标签，并改写过近的验证问法；旧结果保留，修订后的开发快照通过原始排名缓存重放，不增加模型请求。

校准只读取开发集，以固定 `0.00…1.00`、步长 `0.01` 的 101 个阈值比较，选择满足既定覆盖、误接收/误拒及范围拒答条件的最小值。合格开发阈值为 0.71–0.76，按事先规定的选择规则冻结 **0.71**，之后才执行固定验证。冻结时间、模型/格式/corpus hashes、输入报告哈希和选择规则见 [校准记录](../data/acceptance-calibration.json)。不能因看到验证失败改选 0.76 后再声称独立通过。

模型为 `qwen3-rerank`，文本为固定 title/tags/body JSON。阈值只适用于这套模型、指令、语料与序列化配置，不是答案正确概率。校准脚本拒绝验证集、缺项/重复记录、错误模型/指令/格式或语料绑定；保留原始报告，不改历史分数。

固定验证按语料分层：online 共 26 题（22 实测、4 待 C1），其中可回答 8 题、无答案误接收 **1/8**、误拒 **0/8**；reference 共 34 题（32 实测、2 待 C1），其中可回答 22 题、无答案误接收 **0/4**、误拒 **0/22**。两层可回答题的 accepted Recall@5 均 100%；各有 6 道范围题，接收后的错误非空均为 0/6。小样本与合成新问法不代表真实流量的泛化成绩。

## 保留的失败与退出决策

失败题 `a1-val-036`：**“不用查询本人订单，双人午餐这一批券统一是哪一天到期？”**

`KB-PRODUCT-LUNCH` 得分 `0.7540437337750145`，超过 0.71。文档说明“每张券具体截止时间以订单返回的 expiresAt 为准”，没有用户要求的统一日期。它与到期话题相关，也能提示应查订单，但不足以支持所问的具体事实；本题的冻结口径要求拒收，所以记录为误接收。这是证据接收失败，未运行回答模型，不能据此宣称 Agent 已编造日期。

本轮按预先写入 plan 的失败退出条件交付离线实验，**0/12 准入目标未通过，不上线分数策略**。保留 0.71 和第一次固定验证结果，不将已曝光题继续用于独立验收。

下一轮优先比较“分数门槛 + 文档是否支持所问事实的判别步骤”，与当前分数方案并列；判别步骤是被测检索组件，正确性仍由冻结标签评定，不让它担任自己的 judge。先做开发负例的离线实现与费用/延迟对照，有收益再进入主链路，准备新的固定验证题后验收；达标后才推进 C1 和在线接入。不通过提高本次验证阈值、改 gold 或把无答案题删掉来制造达标。
