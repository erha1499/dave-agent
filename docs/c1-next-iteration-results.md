## 实现与代价

| 问题 | 本轮实现 | 限制与成本 |
| --- | --- | --- |
| 最近展示金额被当作用户指定基准 | Session 保存至多两个真实展示来源及溢出状态；15 分钟有效期、版本与用户/群绑定。多候选由用户精确选择，下一轮重新读取本人订单后比较 | 歧义多一轮交互。选择轮零模型/业务调用；仅支持同单、唯一剩余券与可靠实付，不能推导批准金额 |
| policy 分支丢失订单事实 | 两种知识动作复用 fresh 状态、券数量、按状态分组的日期事实；declared 模式检查相同必要前提。区分当前订单与保留条件的规则解释 | 上下文增加；必要前提门控不是完整资格证明。逐字 basis 证明来源，不能确定性证明任意语义；prepare 仍独立重新取证 |
| 泛化澄清无法推进咨询 | 增加金额来源、政策话题、时间/渠道、主体四类宿主固定模板 | 模板不会被模型自由文字替换，但模型仍可能选错类别；普通澄清不等于零模型调用 |
| 旧异步初始化覆盖新回执 | 等待已发焦点写入及旧 Pi 轮次结束；每个异步边界校验当前轮，启动前检查取消 | 复用 Pi 生命周期，不 fork 或另建循环。并发检查证明旧读取/写入及模型事件不污染新轮，取消初始化零 HTTP |

CLI/QQ 本地入口识别当前金额选择回执，避免上一轮模型错误导致新宿主回执被吞掉；本轮没有发送真实 QQ 消息。完整 `npm run validate` 日志为本机 `.runtime/c1-next-final-validate.log`，退出码 0；源码快照、状态/引用变造、过期、相同金额不同来源、跨身份/群、取消及并发均有工程检查。MySQL/真实 QQ 历史结果不能作为该候选的新验收。

## 对照后的接口修复

模型工具 schema 只将固定 `protocol` 改为可省略，宿主补 `v2.2`；若模型提供错误版本仍拒绝。执行入口与 `message_end` 修复计数共用同一 normalizer，内部协议、Controller、历史评分器和业务字段校验不变，不提高 repairBudget。原始模型参数与规范化结果分别保存。Prompt/Skill 同步说明这个输入约定。

工程证明：省略版本在 repairBudget=0 下直接成功，实际 Pi fake HTTP 由 forced→auto 完成；错误版本仍需原预算内纠错，缺少业务字段、额外身份/金额/范围仍拒绝。独立代码审阅及全量 `npm run validate` 通过（`.runtime/c1-protocol-normalization-validate.log`，退出码0）。这项改动不解决竞争指代。
