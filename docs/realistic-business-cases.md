# 模拟售后的真实业务约束

查阅日期：2026-10-05。用于面试项目的场景设计与用例溯源，业务数据、商家结果和资金仍为合成数据。本页区分公开资料的约束、本项目采用的设计和待实现能力；不将平台规则整体复制到演示知识库。

## 面试时可以验证的设计取舍

- **真实约束落在宿主。** 模型提出动作，宿主重新取证和执行；用伪称批准、跨单和重复确认案例说明为什么不能只依赖 Prompt。
- **理解指代与持有权限分开。** 有界订单引用有助于理解“另一张”，实际查询仍重新校验；它不替代 O4 的持久恢复或业务授权。
- **更多检索阶段需要可衡量收益。** 对照 lexical 与 M4 + support 的通过、拒收、失败、延迟和费用。相关分数较高仍不等于原文包含所问事实，服务失败也不能计成正确拒答。
- **小范围真实执行优先。** 用真实模型、真实 MySQL 事务和本地 QQ handler 驱动模拟业务，分别记录外部 QQ 人工验收；未接入的商业能力明确标注。

公开场景补充需沿用上述格式并保持原基线可追溯。若新场景要求额外状态或写入工具，先定义合同与验收条件，再决定实现；不要用条件脚本只匹配用例 ID。
