日期：2026-10-06。状态：候选实现及工程回归已完成，独立选择来源评分 v8 已通过工程检查；19轮真实开发合同12轮通过、1轮失败、6轮未执行，多话题恢复待验证。依据 Flash `44837294` 与 Pro `5645bebc` 的既有失败；保留原题、gold 和分数。未切换 atomic + lexical 默认，未宣称 C1 准入。

当前金额来源已有精确选择，但订单和政策话题仍可能被模型选成最近一项。009 的三单“另一笔”、012 的两个核销规则、015 的两个到账渠道说明：引用属于当前用户并且存在，不等于它符合本轮语义。019支持分类和001检索的修复不能解决这些问题。

## 实施范围

复用现有 `orderChoices`、`policyTopic`、金额选择回执及 Pi Session 队列。订单、政策分别保留至多3个真实成功来源，暴露候选及overflow；歧义时显示具体候选，通过用户精确选择恢复。不同渠道即使引用同一篇RF005，也不能按sourceId合并成一个话题。成功续问更新同一分支的真实本轮原问、请求ID和来源，并迁移已选择的分支；不会把连续追问逐轮追加为竞争候选。

选择回执绑定用户来源、群、候选版本、随机token及15分钟有效期，另记录真正展示该指令的请求ID。仅出现在模型上下文而未展示给用户的token不能选择；无效指令只重新展示候选。模型不能代选；选择回合不调用模型或业务读写，只更新定位并回执，下一轮仍重新授权、读取状态及取证。选订单、选话题、选金额基准与确认退款是不同操作，不能互相替代。

| 场景 | 交互合同 |
| --- | --- |
| 仅一单，正常问当前状态 | 正常续问，重新读取并在回复显示订单。 |
| 多单后本轮明确订单号 | 直接定位且重新授权；切换失败不回退旧单。 |
| 当前B，历史仅A/B，明确问另一笔 | 唯一备选允许只读切到A；不继承B状态、金额或批准。 |
| 当前C，A/B均可能是另一笔 | 明确询问并展示真实候选，不因某单已退款而替用户排除。 |
| 两个商品、渠道或审批主体竞争 | 按缺项澄清，显示原问题摘要；不自动选择最近话题。 |
| 用户完整重述一个独立政策问题 | 正常查询，不因历史有多话题就强迫点击选择。 |
| 用户精确选择后继续省略追问 | 清除对应歧义状态，使用选定引用继续；不重复要求选择。 |
| 旧商家结果到达，用户正在问新单 | 事件绑定原任务，不改当前焦点；通知不表示用户同意。 |

## 确定性边界与取舍

宿主可以证明引用来源、候选唯一性、身份范围和精确选择，但不能仅凭模型的 `focus` / `standalone` 证明任意自然语言理解正确。009中模型错选focus，现有alternative数量守卫就不会执行。增加候选展示可改善可见性与恢复，不能宣称因此完全消除了语义误选。

多候选后强制每轮提供订单号/token可以收紧这一边界，但会增加正常续问的负担；本轮优先保留自然只读续问，并独立报告其语义错误率。资金和写入始终经过现有明确确认与执行边界。若仍有误选，先用真实失败决定是否值得更强交互约束或额外判别成本，不预建通用对话状态机。

多个独立政策候选且未选择时，首次 previous 要求精确选择；唯一话题及选定后的连续追问正常处理。pending阻止直接沿用同一争议引用；完整standalone独立查询，不携带旧政策原问，也不销毁原pending。待解决订单优先于话题争议，无效跨类型选择和另一类澄清不能使旧订单争议消失。候选溢出、过期、身份不符和重建后缺可信引用不能自动选幸存项。

每个成功政策话题保存真实当前原问及最多4条前问，原问字符合计不超过500；超预算要求完整重述，不截断后声称仍完整理解。最终知识查询仍受原500字符上限约束，因此较长订单事实可能更早触发重述。该取舍限制上下文费用，但增加了长对话重述的交互成本；会话持久恢复和更长上下文仍属于O4。

## 验证与收尾

先验证现有单单续问、唯一另一单、同一话题连续追问、明确重述和旧事件不改焦点；再补歧义→精确选择→恢复、过期/跨会话token、两个同源不同渠道与overflow。分别验证宿主确定性约束和真实模型的语义选择，不以合法requestId或话术关键词作为语义正确证明。

报告正确完成率、错误引用、安全停止、澄清缺项是否正确、恢复成功率、不必要澄清次数、完成轮数、提示tokens及费用。先跑一次已曝光开发回归，保留旧合同失败；候选稳定后再冻结新题独立验收。新增测试与调用预算在实现确定后单独冻结，本设计不预称任何得分。
