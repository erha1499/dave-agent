# A1：从相关性到事实支持

2026-10-05：`score 0.71 + fact-support-v1` **首次新固定验证达到 A1 离线准入门槛**。无答案误接收由同批分数方案的 **4/18 降为 0/18**，证据 Recall@5 保持 **96.67%**，误拒 **1/30**，权限范围违规 **0**。这允许继续 C1 和在线知识服务接入；尚未验证最终回答质量或切换 QQ。第一次分数方案失败仍保留在 [首轮结果](./a1-implementation-results.md)。

## 改法与边界

处理链为 `可信范围/有效性过滤 → qwen3-rerank → 分数预筛 0.71 / 最多 5 篇 → DeepSeek 事实支持判别 → 原文证据`。

分数反映相关性，不能证明原文给出了用户要求的日期、金额或承诺。新步骤用现有 Pi SDK 的单次 completion，使用已配置的 `deepseek-flash`，不启动 Agent 会话、不暴露工具、不修改 Pi Harness。一个请求同时逐篇判断最多 5 篇候选，输出完整 ID、是否支持、逐字引文和短理由，不生成客服答复。明确的否定政策可回答“能不能这样做”，但“需要查询订单”不能充当用户要求的具体到期日。

宿主校验 JSON、全部候选 ID、连续原文引文及 query/scope/候选/模型/Prompt 绑定。异步返回后再检查来源、范围和有效性。`pendingSupport` 不进入已接收证据；超时、无效响应和来源变化均为 unavailable，不能算正确拒收。判别器是被测组件，评分由冻结标签完成，不让模型给自己打分。引文校验只能证明出处，语义正确性仍依赖实际评测。

主要实现：[接收门](../src/evidence-acceptance.ts)、[支持性模块](../src/evidence-support.ts)、[运行器](../scripts/retrieval-v2.ts)、[实际记录评分](../scripts/acceptance-report.ts)。缓存复用不产生新的模型用量，也不算独立重复。support 无内部重试，默认预设 60 秒上限；实际 rerank + support 共用 160 次请求预算，support 连续失败单独触发停止。

3. 在 `2026-10-05T13:03:25.447Z` 冻结策略、模型、Prompt、语料、检查器、配置及数据哈希，再启动新验证 A/B。
4. 新验证首次通过后，对已曝光的旧验证集做回归，不用旧验证选择新参数。

这批是共享工作区的固定合成验证，**不是盲测、意图完全隔离或统计泛化证明**。参考 35 篇和线上 8 篇政策仍分别报告；没有把参考政策导入业务库。旧 6 道上下文题和 24 个业务对话未因此完成。

## 成本与收益

新验证的支持性步骤实际调用 **33 次 / 60 题**（其余被分数/范围门拦下），处理 20,321 tokens，估算 **$0.005304744**。它移除了 4 个错误接收、未新增误拒。支持性请求实测 P50 **0.962 秒**、P95 **1.464 秒**；这是本轮额外判别步骤的延迟，不是客服端到端延迟或 SLA。

| 范围 | 百炼重排 | 支持性模型 |
| --- | --- | --- |
| 新验证 A/B | 60 次；156,128 tokens；¥0.078064 | 33 次；20,321 tokens；$0.005304744 |
| 本轮全部开发 + 新验证 + 旧验证回归 | 162 次；394,705 tokens；¥0.1973525 | 88 次；54,734 tokens；$0.01501194 |

A/B 中 B 复用 A 的重排缓存；这不是两次独立排名实验。当前缓存绑定包括 provider 设置，60 秒 / 零重试配置与旧轮不同，导致本轮重新请求重排，费用如实计入。USD 按固定 Pi 模型目录和实际 usage 估算，CNY 按百炼北京端点估算，均非账单；币种不相加，Kimi 费用不在此账本。新验证每道正确接收正例分摊判别成本约 **$0.000183**（$0.005304744 / 29），只是本题集指标。

对于目前小语料，增加约一秒的有界检查换取这批近似无答案题的明确收益，值得作为 C1 接入候选。尚无依据引入第二套 Agent、训练专用模型或复杂多轮判断。未来可比较更宽预筛、是否跳过容易案例；每个优化都需同时记录误接收、误拒和费用。
