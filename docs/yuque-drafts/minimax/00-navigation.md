# 00｜学习导航：阅读路线与面试地图

## 先用一个问题认识项目

用户买了一张团购券，因为门店不能履约而想退款。客服要先确认这是谁的订单，查看券是否使用过和适用规则；需要联系商家时取得用户明确同意，等待商家结果；能够退款时展示具体方案，再由用户确认，最后在事务中执行并保存结果。

Dave-Agent 用这个场景学习 Agent 工程：模型负责理解与组织语言，宿主负责接待流程，工具和存储守住身份、金额、确认与幂等。Pi 提供模型与工具的循环；项目代码把这套通用循环接到具体业务上。

订单、商家结果和资金使用合成数据，身份与状态检查由真实代码和存储执行。完整售后链在对应接待入口中讲解；网页入口目前只提供咨询。学完以后，应能解释一次正常请求怎样完成，以及断线、重启、身份变化和重复请求时怎样继续。

## 阅读前认识六个词

| 术语 | 本项目中的含义 |
| --- | --- |
| 宿主 / Harness | 接收输入、组织模型与工具、管理会话和检查结果的外层程序 |
| 工具 | 模型可以请求执行的受限业务函数，例如查本人订单 |
| 可信身份 | 入口与数据库绑定确定的客户身份，不接受用户自报替换 |
| 幂等 | 同一业务操作重复到达时，不产生第二份业务效果 |
| 事务 | 多个数据库变更作为整体提交或回滚 |
| RAG | 先检索相关资料，再让模型利用资料回答；检索结果仍需检查适用性 |

这些术语会在相关课程用具体例子展开，不需要先记住所有内部名字。

## 用一条消息串起各章

把自己放在客服的位置，收到“这张券我还没用，帮我退一下”。先不要急着调用退款工具。

1. **入口与身份**：系统知道哪个客户在说话，但还需要定位订单。没有订单号时，只能列出本人最近订单供选择。
2. **当前事实与规则**：重新读取订单状态，再查询与门店、商品和时间范围一致的规则。旧回复不能替代当前状态。
3. **业务动作**：确认用户具体想做什么。联系商家、接受退款方案和执行退款是不同动作，不能互相替代。
4. **等待与恢复**：商家处理可能晚于这一轮聊天。把任务保存下来，用户可以继续问别的问题；结果通知仍要回到正确身份和会话。
5. **执行与回执**：用户看见具体方案并精确确认后，事务重新检查条件，成功只记一笔退款。网络没回包时先查持久结果。
6. **评测与表达**：用可检查的工具调用和状态变化判断是否完成；保留失败、未执行与未知费用，再说明为什么选择这个方案。

这个顺序也是阅读源码的顺序：入口 → 宿主 → 工具 → 存储 → 回复。遇到一个函数时，先问它接受什么输入、信任哪些信息、拒绝什么情况、留下什么结果。

## 三种学习方式

**第一次学习**：按表格顺序读。先把身份、售后事务和失败恢复讲通，再读检索方案与模型对照。不要把更复杂的检索链自动当成默认实现。

**带着故障学习**：页面重试与串话读 06.20；模型超时后下一条消息卡住读 03.50；截止后晚到批准读 03.20；商家通知未知读 03.40；剩余金额能否直接退读部分核销案例。

**准备面试**：先用 01.00 讲项目分工，再选 03.30、03.40 或 06.20 中一个失败场景讲到代码，最后用 07.10 和 07.20 解释验证与成本。07.30 提供项目表述和追问练习，但不要只背那一篇。

## 怎样判断自己学会了

给自己四个检查任务：

- 不看内部阶段名称，说出一次退款从咨询到回执经过哪些判断。
- 对照正文源码，指出身份、金额和确认分别在哪里检查，模型为什么不能跳过。
- 任选一个失败场景，解释数据库留下什么、用户看见什么、下一步能安全做什么。
- 比较一个替代方案，说明收益与代价，而不是只说使用了哪些技术。

每篇末尾的练习都围绕这四点。核心能力不是记住函数名，而是能从一个用户问题推导需要哪些数据、权限、状态和恢复动作。

## 参考资料与实现边界

教学实现来源于本项目 `src/`、`scripts/` 与现有业务说明。各篇已就地展示相关核心源码，并在末尾列出实现位置。订单、资金和商家结果为合成数据；真实模型小样本、工程检查和真实平台传输是不同验证层次，不应合并表述为生产效果。

当前默认接待路径与实验候选会用自然语言说明。检索实验、持久业务定位和完整共同评测有各自适用范围，阅读优化方案不表示全部候选已经进入默认路径。
