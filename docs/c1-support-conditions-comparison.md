# C1 条件覆盖：v6 / v7 固定输入对照

日期：2026-10-06。状态：开发候选已实现，全量工程检查通过，固定对照待执行。本轮不改变 typed v5 默认或 QQ 配置，也不把组件结果当作 C1 准入。

## 问题与假设

[19 轮开发探针](./c1-reference-selection-validation.md)的银行卡咨询接收了 RF005 与额外 RF001，严格证据合同失败。RF001 的一般到账数字相同，却明示具体时限以支付渠道为准，没有独立提供银行卡结论；同批信用卡咨询反而拒收了它。假设是：把条件覆盖要求明确扩展到一般/假设规则，并区分“通用规则覆盖子类”与“具体结果留给子类规则”，可降低这类误接收。

v7 仅在完整 v6 前增加通用条件合同，保持输出分类、逐候选校验、模型和重试不变。没有加入题目 ID、特定渠道或时限特判。v5 默认与 v6 字节和哈希锁定；不新增模型阶段、结构化 slot schema 或检索阈值调整。这样先验证一个成本较低的修正，保留现有 Pi 与知识服务设计。

工程核验：`npm run validate` 通过；覆盖 v5/v6 提示词与请求兼容、v7 请求绑定、逐候选及无效项计分、计划分母保留、未知用量和真实请求硬预算。数据独立审阅已核对原始失败输入与历史哈希，以及旧回归的 query、scope、候选和 gold。本段属于零远程调用工程证据，不计为模型效果。

## 固定开发输入

[数据文件](../data/c1-support-conditions-development.json)包含12个输入，每版本15个候选判断（9正、6负）。001精确重建上次失败的完整支持判别输入，并核对历史 inputHash；002/003只改变候选集合，004/005只改变明确渠道。其余来源与修改范围逐条记录，全文、tags、候选顺序、query及gold在请求前冻结。

| 输入 | 用途与预期 |
| --- | --- |
| 001 银行卡，RF005 + RF001 | RF005 direct_fact；RF001 limitation_only，不借相同数字或另一篇补渠道依据。 |
| 002 银行卡，仅 RF001 | 检查单篇是否仍被错误接收，排除同批其他文档补足。 |
| 003 银行卡，仅 RF005 | 必须保留明确渠道时限正例。 |
| 004 信用卡、005余额，各两篇 | RF005均正、RF001均负，检查渠道变化后的条件一致性。 |
| 006 未核销券一般时限，仅 RF001 | 用户明确保留一般时限与支付渠道例外，RF001可回答。 |
| 007 银行卡未核销券原路退款 | 通用路径规则适用于银行卡子类，不要求文中逐字出现银行卡；用于防止修复过严。 |
| 008审批流程 / 009已经批准 | 沿用既有真实规则正例与实例状态负例，不将待审批升级为已批准。 |
| 010具体过敏原 / 011资料覆盖 | 逐字保留既有019/023完整上下文，维持事实与元边界区分。 |
| 012周日续问 | 逐字保留既有语言005；允许条件式语言包含关系，旧误拒如仍存在须保留。 |

这是已曝光问题驱动的开发对照。15个候选判断不是15个独立问题，24次请求也不是24个独立业务场景；无 Agent、rerank、SQL、QQ 或最终答复评测。

## 预算与推进条件

同一 DeepSeek Pro、temperature 0、maxTokens 2048、provider重试0，只有 v6/v7 的提示词内容及版本不同；按题交替先后顺序。预建两组各12行，失败、invalid、未执行及未知用量保留；partial/invalid不能计为正确拒收。

硬上限24次真实 support HTTP，总时限5分钟、单次60秒，已知费用达USD 0.06后停止下一请求，最后在途请求可能越过软线。每个manifest只允许一次执行，记录实际请求、tokens、估算费用和延迟；费用不是账单，unknown不补零。

推进前必须完整执行并核验版本、用量及输入；v7去掉001/002银行卡对RF001的误接收，保留003/006/007和其他目标正例，且不增加同批v6已通过的回归失败。至少出现一项同批目标改进才称为有效果收益；若两组相同则记录本批未观察到收益。周日旧失败不因此放宽标签。达标后才考虑把候选接回完整Session，另冻新manifest；原19轮12/19结果和原gold永久保留。

## 复现入口

复用现有[支持判别对照脚本](../scripts/c1-support-intent-development.ts)，原默认 intent 对照仍有独立数据及manifest；新增 conditions 只切换这组输入、版本、预算和统计口径。

```sh
node scripts/c1-support-intent-development.ts --suite conditions --check
node --env-file-if-exists=.env scripts/c1-support-intent-development.ts --suite conditions --freeze
node --env-file-if-exists=.env scripts/c1-support-intent-development.ts --suite conditions --inspect
# 仅在固定输入/源码/预算均核对后单次执行
node --env-file-if-exists=.env scripts/c1-support-intent-development.ts --suite conditions --live
```

按完整输入精确通过率和逐候选误接收/误拒分别报告；记录类别与reason诊断、单版本实际HTTP/用量/费用、P50/P95和失败。结论需结合额外上下文tokens与延迟，不能只展示更高分数。
