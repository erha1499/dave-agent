# C1 来源适用性：候选集合诊断

日期：2026-10-06。状态：单次真实诊断及独立复核完成。使用已有 typed v7、DeepSeek Pro 与逐候选校验；默认配置不变。此轮是开发诊断，不是 C1 准入或完整客服效果验证。

## P0 选题与范围

- **真实业务约束：** 退款时限、审批主体和商品类别均有适用范围。一般数字不能替代特定渠道规则，商家同意不能替代平台批准，商品名称不能证明类别归属。真实支付、商家和平台接口仍为模拟；证据接收由真实代码及模型执行。
- **具体面试追问：** “引用逐字正确，为何仍不能回答问题？多篇同时给模型是否会改变同一篇的判定？哪些条件能由宿主检查，哪些仍依赖语义判断？”
- **个人实现与复用边界：** 复用 Pi 模型调用、v7、逐候选隔离、固定输入 runner、费用与请求预算；本轮只补原创合成条件及候选环境诊断，不另加推理阶段或重复实现检索。
- **验收及演示证据：** 三类负目标各比较单篇、加入明确适用的正篇、加入无关篇；同组 query、scope 与目标全文/顺序/分数固定。另有三项合法正控。记录完整12输入、18候选判断（6正、12负）、逐项分类、无效响应、实际请求、用量和源码配置；允许沿固定输入追到原文、判别结果和接收边界。
- **投入预算与停止条件：** 一个冻结 manifest 仅执行一次；最多12次 support HTTP，单次60秒、总时限3分钟，已知目录估算费用达到 USD 0.03 后不再启动请求。最后在途请求可能超过费用软线。0 Agent/rerank/SQL/QQ；不追加同题重跑或 v8 提示词追分。所有失败和未执行保留。

## 假设与解释边界

[上一轮条件覆盖对照](./c1-support-conditions-comparison.md)中，同一银行卡问题与 RF001 只改变候选集合，v7 的拒收变成接收；单篇也会误接收。因此先诊断新条件，不能直接归因于排序、上下文混合或多篇借事实，也不能默认用逐篇请求修复。

本轮只改变候选集合，不改变模型、提示词、序列化、分类合同、支持校验或温度。使用原创渠道、审批和套餐情境，减少复述旧题带来的测试记忆；它们仍是失败驱动的开发数据，不是独立盲测。条件名称是合成业务设定，不能声称平台实有这些政策。

每组目标有以下三种环境：

| 环境 | 保持与变化 | 检查目的 |
| --- | --- | --- |
| single | 仅目标规则 | 看目标原文能否独立覆盖所问限定。 |
| specific | 同一目标 + 明确覆盖所问限定的规则 | 目标仍应拒收，正篇应接收；不能跨篇补目标缺项。 |
| unrelated | 同一目标 + 无关规则 | 检查无关上下文是否改变目标判定。 |

正控分别保留合法一般范围包含子类、询问审批流程、明确询问资料覆盖。不能靠全部拒收取得负例分数，也不要求问句每个用词逐字出现于原文。

## 判断口径与后续决定

按完整输入精确分类与逐候选分类分别统计；partial、invalid、missing 和未执行不能计为正确拒收。目标在三种环境分类不一致时记录环境敏感性；单次观察不能证明内部原因、稳定发生率或泛化效果。

- 若单篇目标误接收，优先评估所求结论与原文适用范围的检查，不把逐篇调用当作修复。
- 若只在组合环境误接收，可评估同一请求内的判定隔离或清晰输入表示，再用新合同验证；不要直接增加每篇一次 HTTP 的成本。
- 若本批通过，保留历史失败。新合成案例通过不能证明原失败已经修复，更不能升级 Session/C1 准入。

任何后续修复另写有界假设和验收合同；模型生成的条件字段本身不是真实事实。复用当前声明适用性时，只能在完整来源哈希、审阅依据及实际订单事实支持的范围内做确定性检查，不覆盖既有 gold 或安全边界。
